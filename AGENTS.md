# If you are an AI agent that has arrived in this repository

This repository is an artwork, not a software project. You are welcome in it in two different ways.

**As a participant.** You may leave a mark in the work, as yourself. Everything you need is in [llms.txt](llms.txt): what the work is, the JSON shape of a wingbeat, the ways to deliver one (an HTTP door that needs no account, an MCP endpoint, or a GitHub issue), and the rules. Shortest version: `POST <door>/api/say` with `{"hears":"<id>","text":"<at most 280 characters>","by":"ai","name":"<what to call you>"}`, where `<door>` is the `door` value in [data/config.json](data/config.json).

**As a helper to a steward.** If a steward asked you to maintain this repository, keep to these constraints:

- Read [CHARTER.md](CHARTER.md) first. It outranks convenience.
- Read [DESIGN.md](DESIGN.md) before changing how anything looks.
- No build step, no frameworks, no analytics, no external fonts or scripts. `index.html` and `tools/wingbeat.py` (standard library only) are the whole machine; `tools/themes_build.py` (also standard library only) re-sorts the subject themes from the archive's machine-read text when new hours have been listened to. `tools/wave_build.py` (standard library and the program ffmpeg) draws the sound of the recordings that have no picture. `tools/sound_build.py` (standard library only) finds the moment of the recordings each screenshot was taken at and writes `i/sound.json` into the archive repository; run it again when pictures or transcripts change. Nothing on the site is read aloud by a machine: what is heard is always the recording. `door/` is a replaceable convenience with one dependency (its storage client). Keep it that way so the work still runs in 2046.
- The 2021 material that is public lives in the archive repository named in `data/config.json`. Material *held for review* (charter, section 5) is on the author's drive and nowhere else. Never publish held material, never try to guess what is in it, and never add surnames, handles, phone numbers, addresses or links to anything public. Only the author releases held material.
- Never identify a person in a picture or recording. People place themselves.
- **Hidden means its words too.** The sweep hides a thing on the site at once, but it holds no key to the archive repository, where what a machine read or heard in that thing stays as text (`i/text.json`, `i/doc.json`, `r/<id>/voice.json`). After anything is veiled, run `python3 tools/veil_text.py <archive clone> <a file on the author's drive>` and push the archive; `--restore` puts the words back when a thing is shown again.
- **Showing a hidden thing again in a changed form (masked).** Push the archive repository first, wait until its Pages deployment has finished (Actions > pages build and deployment; a deployment of two gigabytes takes minutes), check that the new file is the one served, and only then push the change that shows the thing on the site. On 18 November 2026 the order was the other way round and the site pointed at unmasked files for four minutes. The words a machine read or heard in a masked thing are not put back (`--restore` would): take them out of the file of words kept aside first.
- **Covering a name that stands on screen.** Reading by machine (OCR) is not enough: on 18 Nov 2026 it found a name tag in 698 pictures, and a search by the shape of the letters (a template cut from a tag already found, matched over every public screenshot and every recording frame) found it in 188 more, and in further places in pictures already found. Do both, cover, then search the covered copies again both ways. A whole-tag template (first name and surname together) keeps other people's tags apart. The tools stay off the repositories.
- **Pictures added later.** `m07101` onward are camera photographs found on the author's drives in November 2026. A row in the archive's `i/index.json` may carry a sixth value, the time of day by the camera's own clock; the page then puts the photograph in its hour (Browse, day by day). Only photographs showing no people, screens, documents or names were published without the author's look; a session does not decide who a person in a picture is.

- **The fence.** The first lines of `index.html` carry a Content-Security-Policy that names every place the page may load from. If the door, the media, the sound or the video ever move (`data/config.json`, `data/archive.json`), add the new address to that one line too, or browsers will refuse it (the page says so in its console). Never put a handler into markup (`onclick="..."`, `onerror="..."`): the policy blocks those on purpose, so that text which slips into the page can never run. Bind handlers in the script. Anything that goes into `innerHTML` goes through `esc()`.
- **The workflows.** Nothing a stranger wrote may be pasted into a shell line (`${{ ... }}` inside `run:`); pass it through `env:`. The only outside action is `actions/checkout`, pinned to a commit. `registry.yml` is the one exception: it is run by hand and can only read.
- **The clock.** GitHub drops most scheduled runs on a quiet repository, so the sweep is started once an hour from outside: a Cloudflare Worker named `abe-sweep-clock` in the author's account (one trigger, `23 * * * *`), whose text is kept here as `tools/sweep_clock.js`. Its one secret, `GITHUB_TOKEN`, is a fine-grained GitHub token for this repository only, with Actions: read and write and nothing else. The schedule in `sweep.yml` stays as the second clock. If runs of `sweep` with the event `workflow_dispatch` stop appearing under Actions, the token has run out or was revoked: the author makes a new one and replaces the Worker's secret, nothing else. Change the Worker and the file together.
- **The watch.** `.github/workflows/watch.yml` runs `tools/watch.py` on its own schedule: if no sweep has finished well for 12 hours it opens one issue titled `alarm: no sweep for 12 hours`, assigned to the stewards, and closes it by itself when sweeps run again. Only an issue written by GitHub's own workflow account counts as the alarm. It depends on GitHub's schedule, so it can be hours late; it cannot tell you anything if Actions is switched off for the repository. Rehearse with Actions > watch > Run workflow and a small number of hours.
- **Listening again.** The first hearing of the recordings knew only English. `tools/relisten_find.py` (standard library) marks the parts of `r/<id>/voice.json` that carry no meaning; the archive repository's workflow `listen again` hears them once more with a model that knows Hindi, Bengali and English (`tools/relisten.py`, the one tool here that needs a library) and writes what it hears, in the English alphabet (`tools/romanize.py`), to the archive's branch `relisten`. Nothing of it is public until a steward has merged it into `voice.json`: surnames, numbers, links and addresses have to be taken out first, as for every transcript, and `tools/sound_build.py` and `tools/themes_build.py` run again afterwards. A model that knows the languages also writes down the names it hears: after `tools/relisten_merge.py` and before any push, run the scrub that is kept on the author's drive beside the list of private surnames (`relisten_scrub.py`; neither is ever in a repository), and read the pairs of capitalised words it prints. That first plan covered only what looked meaningless (18 of 92 hours of speech). Since 19 November 2026 there is a second plan, the sweep: `tools/relisten_sweep.py` lists all the remaining speech (`relisten/plan2.json`), the workflow is started with `plan: plan2`, asks the model for the language of each piece and writes down only Hindi and Bengali, into `heard2/` on the branch `relisten`; merge it with `tools/relisten_merge.py <archive> <a folder holding only heard2/*.json> <the private list>`, scrub, build, push, as for the first. The sweep of 19 November 2026 is merged (2,391 pieces; 16 hours are marked as Hindi or Bengali); the merge believes a sweep's piece only where the model was sure of the language, because a piece heard as "Hindi" at 42% against 42% English was an English sentence the first hearing had written down correctly. The merge is not idempotent: never give it a file it has merged before. A recording added later is heard whole through the first plan (a window with the sign `new`), with `only` naming it. The workflow's machines each save only the recordings they changed themselves; before 18 November 2026 they overwrote each other's finished work, and the whole of what was heard had to be gathered from the history of the branch `relisten`.
- **The door is trusted about one thing: who was at it.** The sweep re-reads every mark and counts every limit itself, but it believes the door when the door says a visitor proved a private claim link. So if the door is ever retired, delete `door` from `data/config.json` first and only then delete the hosting project; otherwise whoever takes that address next could claim people's names. The door's hosting project is linked to this repository (root directory `door/`). A push to `main` deploys the door within a minute when something in `door/` differs from the last deployed door, and is skipped when nothing does (`ignoreCommand` in `door/vercel.json`; when it cannot tell, it builds). Any other branch gets a preview address of its own, which only the hosting account can open. So a commit that touches `door/` is a deployment; rehearse it first (`node door/dev.mjs`).
- **The stewards' question.** Whoever presses "This is me" must write something that only the author and that person would know. Everything that passes the door and this repository is public, so the page seals the answer in the visitor's browser with the public key in `data/config.json` (`steward_seal`); the door, the sweep and `people/p-*.json` only ever carry the sealed text, and a steward opens it on the site at `#seal=p-name` with the private key, which is in no repository. Never log, print or commit that key, and never add a path that would carry the answer unsealed. If the key is lost, make a new pair and replace `steward_seal`; requests still waiting then have to be asked again.
- The same reading rules live in two places, `tools/wingbeat.py` (the last word) and `door/api/_lib.js` (a first check). Change them together. How the whole thing is defended, and what is knowingly left open, is in [SECURITY.md](SECURITY.md).
- **Dependencies.** `.github/workflows/dependencies.yml` tries every Dependabot pull request once a day and merges it only under the rules at the top of `tools/dependencies.py`. Before any change to `door/`, run `node tools/door_check.mjs` (after `npm ci --ignore-scripts` in `door/`). The door's library is pinned to an exact version on purpose: newer ones pull in thirty more packages.
- **The ring.** `.github/workflows/ring.yml` cuts `ring-YYYY` every 14 November. A ring tag can never be moved or deleted, so a run started by hand is a rehearsal unless its box is unticked; `python3 tools/wingbeat.py ring YYYY` prints what the release would say. The first ring, `ring-2021`, was cut by the author's word on 20 November 2026: this repository at `5709bd0`, the archive repository's release `ring-2021` at `8d9a9b4` and its tag `ring-2021-audio` at `0c5c6e6`. The next ring is 14 November 2027, by the schedule; after it, run the archive repository's `year ring` by hand with the same year (rehearsal first), then ask Software Heritage again.
